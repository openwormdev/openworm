# WormStreet

A public-safe, paper-only laboratory that feeds market-shaped sensory currents into a **real c302 C1 model**, reads named command neurons, and shows who made each decision.

This is an experimental connectome controller, not a validated animal mind or a profitable trading strategy. No wallets, private keys, real orders, analytics, accounts, or personal profiles are included.

## What works

- A dependency-free dashboard: play, pause, scrub, change scenarios, inspect currents and voltages, inspect risk decisions, and export a report.
- Bundled recordings generated by actual c302 C1 models, exported through jNeuroML and executed by NEURON, using fictional market observations. The page labels them as recordings, not live simulations.
- A Python/Java reference worker that generates the full neuron network available in the pinned c302 reader and runs new simulations. The actual population count is reported, never hardcoded as 302.
- One continuous worm per token replay. A new replay starts a new model state.
- A separate paper portfolio with entry confirmation, fees, slippage, impact, position limits, external vetoes, and explicitly unfilled exits.
- A hash-linked decision audit trail and an integrity manifest for bundled recordings.
- Local report import: files are parsed in the browser, not uploaded. Imported simulation origins are marked unverified.
- Vercel configuration for the static dashboard; deployment remains your choice.

## Run the full laboratory locally

Requirements: Linux, Python 3.12, Java 17+, GCC/G++ and Make, and Node 22+ for web checks/builds. The committed Python lock was tested on Linux with Python 3.12. Native Windows support is not implemented; use WSL2 or Docker. Other platforms may need separate resolution and compiler support.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.lock
pip install --no-deps -e .
wormstreet doctor
wormstreet serve
```

Open `http://127.0.0.1:8000`. Recordings work immediately. To calculate new activity, leave the worker URL blank and choose **Run real c302 simulation**. Full-network runs are CPU-intensive; only one runs at a time.

Do not put credentials in command arguments or source files. The NEURON exporter compiles the generated NMODL mechanisms with GCC/G++; this is why a C++ toolchain is required.

## Run a reference replay without the browser

```bash
wormstreet replay --scenario reversal --output runs/reversal.json
wormstreet replay --scenario trend --output runs/trend.json
wormstreet replay --scenario liquidity-shock --output runs/shock.json
```

`runs/` is ignored by Git. The output report can be opened in the dashboard. Regenerate public recordings only from the built-in fictional scenarios:

```bash
make recordings PYTHON=.venv/bin/python
npm test
npm run check
npm run build
```

## Replay your own observations

```bash
wormstreet replay --input runs/observations.json --output runs/report.json
```

The input is a JSON array of 2–24 consecutive observations at 15-second intervals. Each entry must contain `tick`, `seconds`, positive `price`, `flow` in [-1,1], nonnegative `liquidity`, nonnegative `price_impact_bps`, and boolean `fresh` and `eligible`. See `examples/observations.json` for a fictional example.

This path is offline replay, not live data ingestion. Eligibility, freshness, and price-impact fields supplied in an input file are **unverified assertions**, not contract safety checks or executable exchange quotes. The report says `user-provided-unverified`. Do not publish private inputs or their exported reports.

## Deploy the public laboratory

The repository includes a GitHub Pages workflow. On the `main` branch it validates the bundled recordings, runs the privacy scan, builds the static site, and deploys `dist/`. The browser uses repository-relative asset URLs, so both a custom domain and a GitHub project page work without path rewrites.

For Vercel, import this GitHub repository. Use the repository root, framework **Other**, Node 22+, build command `npm run build`, and output directory `dist`. `vercel.json` already supplies the build settings and security headers. `npm ci` needs no third-party JavaScript packages.

The deployment runs the dashboard and bundled recordings only. It does **not** run Java, the Python worker, a continuous trading bot, or real trades. Do not put a worker credential in Vercel public variables or static files.

For fresh simulations from the deployed page, host the Python worker separately on a VM/container with Java, set its allowed browser origin and a secret token server-side, then enter that worker's HTTPS origin and token in the dashboard. Credentials stay in memory; requests reject redirects.

```bash
docker build -t wormstreet-worker .
docker run --rm -p 8000:8000 --env-file .env wormstreet-worker
```

Copy `.env.example` to an ignored `.env` and populate it privately. Set `WORM_ALLOWED_ORIGINS` to your exact dashboard origin, with no wildcard, and set a high-entropy `WORM_WORKER_TOKEN`. The worker denies remote simulations if no token is configured. Put it behind TLS and host-level rate limits; do not expose an anonymous CPU-work endpoint. Docker does not need any blockchain secret.

## The 1:1 boundary

1. One replay is one token and one independent neural state.
2. ASEL receives an engineered positive-gradient current; ASER receives a negative-gradient current. Their functional left/right difference is not erased by stimulating both identically.
3. AWA/AWC pairs receive engineered attractive-flow input. ASH pairs receive engineered aversive input.
4. The full selected c302 network propagates the stimulus; no conventional trading score replaces neural output.
5. AVB/PVC output is compared with AVA/AVD/AVE output. A fixed readout and hysteresis produce `ENTER`, `HOLD`, or `EXIT`.
6. The independent risk engine may block entries or request an exit. Its intervention never rewrites the original worm intent.
7. The paper executor applies fictional fills and costs. An unsafe exit can remain unfilled; no real order method exists.

“1:1” does **not** mean biologically exact. The connectome, generic C1 cell parameters, imposed inputs, missing body feedback, and chosen financial readout are different sources of uncertainty. A zero-trade result is shown honestly.

## Not implemented / not claimed

- Continuous mainnet ingestion, launch sniping, on-chain contract safety verification, or Jupiter order execution.
- Durable multi-user accounts or an always-on autonomous trader. Worker jobs are bounded, in-memory, and reset on process restart.
- P&L training, native worm financial learning, optimized profitability, or a fast surrogate described as the real model.
- Scientifically calibrated behavior or proof that the connectome beats momentum/random/rewired baselines.

Those are separate milestones. Live execution should not be added until data provenance, token safety, transaction inspection, signer isolation, balance reconciliation, and adversarial recovery tests have been implemented and reviewed.
